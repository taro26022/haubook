# 家計簿アプリ 仕様(最初の版 1.0.0)

引き継ぎ資料(`taro26022/calendar` の `docs/handoff-kakeibo.md`)で決まっていたことに加えて、
実装時に決めた内容をここに記録する。

## 1. 引き継ぎ資料で決まっていたこと(要約)

- 目的: 1週間の収支を知り、生活の質を上げる
- 形式: Web アプリ(PWA)。iPhone のホーム画面に追加して使う
- データ: 端末の中だけに保存。サーバーなし、同期なし。JSON ファイルで書き出し・読み込み
- 公開: GitHub Pages(公開リポジトリ `taro26022/haubook`)
- 機能: 収支の入力、一覧の表示・編集・削除、週の集計、カテゴリの追加・変更、バックアップ
- 週の始まりは月曜日。通貨は日本円(整数)。画面は日本語
- 外部サービス(解析、広告、外部 API)は使わない

## 2. 実装時に決めたこと

### 2-1. 技術構成

| 項目 | 決めた内容 | 理由 |
|---|---|---|
| フレームワーク | 使わない(素の HTML / CSS / JavaScript) | Mac に Node.js がなく、ビルドの手順も不要にしたい。ファイルをそのまま GitHub Pages に置けば動く |
| JavaScript の分け方 | ES モジュールで役割ごとにファイルを分ける | 計算の処理(日付・金額・集計・バックアップ)を画面の処理と分け、テストしやすくする |
| 保存方式 | IndexedDB | localStorage より容量が大きく、トランザクションで安全に書き込める |
| 永続保存の要求 | 起動時に `navigator.storage.persist()` を呼ぶ | ブラウザがデータを自動で消す可能性を下げる。結果は設定画面に表示する |
| オフライン対応 | Service Worker(ネットワーク優先、取得できないときはキャッシュ) | 電波がなくても開ける。つながるときは常に最新版を使うので、更新のたびにキャッシュ名を変える必要がない |
| アイコン | `tools/make_icons.py` で生成(緑の正方形に白い ¥) | 外部ライブラリなしで作り直せる |

### 2-2. データの形

記録(entries):

| 項目 | 型 | 内容 |
|---|---|---|
| id | 文字列 | UUID |
| date | 文字列 | `YYYY-MM-DD`(端末の時刻で解釈する) |
| amount | 整数 | 1 〜 999,999,999 円 |
| type | 文字列 | `expense`(支出)または `income`(収入) |
| categoryId | 文字列 | カテゴリの id |
| memo | 文字列 | 任意、100 文字まで |
| createdAt / updatedAt | 文字列 | ISO 8601 形式の日時 |

カテゴリ(categories): `id`、`type`(expense / income)、`name`(20 文字まで)、`order`(並び順)。
初期カテゴリの id は `default-expense-1` のような固定値にした。

### 2-3. 画面

| 画面 | 内容 |
|---|---|
| 週の収支(最初の画面) | 週の切り替え(‹ ›、「今週に戻る」)、収入・支出・差額の合計、カテゴリ別の支出(金額の大きい順、割合のバー)、その週の記録を日ごとに表示 |
| 記録の入力・編集 | 右下の「＋」で開く全画面のフォーム。支出/収入、金額、カテゴリ(ボタンで選ぶ)、日付、メモ。記録をタップすると編集、削除もここから |
| 設定 | カテゴリの追加・名前変更・並べ替え・削除、バックアップの書き出し・読み込み、バージョンなど |

決めた細部:

- **一覧は週ごと**に表示する。週の集計と同じ画面で、その週の記録を新しい日付から並べる。
  同じ日の中では、後から登録したものが上。
- 入力の初期値: 日付は今日、種類は支出、カテゴリは並び順で最初のもの。新規入力時は金額欄にすぐ入力できる。
- 保存すると、保存した記録の日付を含む週を表示する。
- 金額は全角数字、カンマ、「¥」「円」が入っていても受け付ける。0 円や小数は受け付けない。
- 差額は「収入 − 支出」。プラスは緑で「+」付き、マイナスはオレンジで表示する。
- カテゴリ別の集計は支出だけ(引き継ぎ資料の指定どおり)。
- 片手で操作しやすいように、主な操作(＋ボタン、タブ、保存ボタン)を画面の下側に置いた。
  入力画面の上部にも「保存」がある。
- ダークモードに対応(iPhone の設定に従う)。

### 2-4. カテゴリの変更

- 追加・名前変更・並べ替え(↑ ↓)ができる。同じ種類の中で同じ名前は使えない。
- **記録で使っているカテゴリは削除できない**(記録のカテゴリが分からなくなるのを防ぐため)。名前の変更はできる。
- 各種類(支出・収入)にカテゴリが最低 1 つ必要。
- 名前を変更すると、過去の記録の表示も新しい名前になる(記録はカテゴリの id を持っているため)。

### 2-5. バックアップ

- 書き出し: ファイル名は `haubook-backup-YYYY-MM-DD.json`。
  iPhone では共有シートを開く(「"ファイル"に保存」で iCloud Drive などに保存できる)。
  パソコンでは通常のダウンロードになる。最後に書き出した日時を設定画面に表示する。
- 読み込み: **今のデータをすべてバックアップの内容に置き換える**(足し合わせはしない)。
  読み込む前に、件数を表示して確認する。
- 読み込む前にファイルの内容を検証し、問題があれば何も変更せずに理由を表示する
  (JSON でない、形式が違う、金額や日付が不正、カテゴリが見つからない、id の重複など)。
- 形式:

```json
{
  "format": "haubook-backup",
  "version": 1,
  "exportedAt": "2026-10-11T06:00:00.000Z",
  "categories": [{ "id": "default-expense-1", "type": "expense", "name": "食費", "order": 0 }],
  "entries": [{ "id": "…", "date": "2026-10-11", "amount": 1280, "type": "expense",
                "categoryId": "default-expense-1", "memo": "", "createdAt": "…", "updatedAt": "…" }]
}
```

## 3. 動作確認の方法

- ローカルで確認する: このフォルダで次のコマンドを実行し、ブラウザで `http://localhost:8000/` を開く。

  ```bash
  python3 -m http.server 8000
  ```

- テスト: 同じくサーバーを動かして `http://localhost:8000/tests/` を開く。
  日付・金額・週の集計・バックアップの検証のテストが動き、結果が表示される。

## 4. 最初の版に入れなかったこと

引き継ぎ資料の「今後の検討事項」(同期、予算、月ごとの集計、グラフ)のほか、次のものは入れていない。

- 記録の検索、全期間の一覧
- バックアップの「足し合わせ」読み込み
- カテゴリの色やアイコン
